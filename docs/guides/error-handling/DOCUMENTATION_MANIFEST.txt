================================================================================
THE PROBLEM SOLVED
================================================================================

Before:
  - Users got cryptic subprocess errors
  - Exit codes provided no context
  - No clear guidance on what to fix
  - Support burden for each user question

After:
  - Clear problem statement
  - Context about what was installed
  - Explanation of why it happened
  - Actionable steps to fix

Error message improvement:
  FROM: CalledProcessError: Command [...] returned non-zero exit status 127
  TO:   RegistryNotFoundError: wt-registry executable not found at '...'
        
        The ephemeral environment was created with the following packages:
          - my-package>=1.0.0
        
        The wt-registry CLI is required for task discovery but was not installed
        because none of the specified packages depend on wt-registry.
        
        To fix this issue, ensure your task packages include wt-registry as a dependency:
          1. Add 'wt-registry' to your package's conda dependencies, OR
          2. Add 'wt-registry' to the requirements in your spec.yaml

================================================================================
FIVE CORE PREVENTION STRATEGIES
================================================================================

1. Explicit Existence Checks Before Subprocess Calls
   - Check preconditions before expensive operations
   - Fail fast with domain-specific errors
   - Enables proactive error messaging

2. Comprehensive Context in Error Messages
   - Include WHAT failed
   - Include WHY it failed
   - Include HOW to fix it

3. Exception Hierarchy for Distinguishing Error Types
   - Domain-specific base exception class
   - Specialized exceptions for each error type
   - Enables selective exception handling

4. Pair Error Checking with Input Validation
   - Validate preconditions before expensive operations
   - Early warnings about likely misconfigurations
   - Prevents wasted computation

5. Test the Unhappy Path
   - Test every error condition
   - Verify error messages are helpful
   - Ensure exception attributes are populated
